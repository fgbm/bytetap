### Добавлено

- Cargo workspace с crates `bytetap-core` (ядро без Tauri), `bytetap-cli` (консольная версия с `--version`) и `bytetap-testkit` (тестовые помощники), версия Rust закреплена в `rust-toolchain.toml`.
- Каркас приложения `app/`: Tauri v2 + Vue 3 + TypeScript + Vite, vue-i18n с единственной локалью ru, окно-заглушка с заголовком «bytetap», vitest с одним тестом.
- Сайт документации на VitePress в `docs/` (`base: /bytetap/`, локальный поиск, разделы `guide/`, `reference/`, `dev/`), битые ссылки ломают сборку.
- npm workspaces `app` и `docs` со скриптами `dev`, `build`, `check`, `docs:dev`, `docs:build`.
- GitHub Actions: `ci.yml` (fmt, clippy, test на Ubuntu и Windows, фронтенд, сайт, Windows exe в артефакт, actionlint), `docs.yml` (публикация сайта на GitHub Pages), `release.yml` (zip с `bytetap.exe`, README, LICENSE, `SHA256SUMS` и черновик релиза по тегу `v*`).
- Иконки-заглушки приложения для Windows-сборки.
- Журнал сессии `bytetap-session/1` (FR-19…FR-24): модель событий `session`, `open`, `data`, `close`, `error`, `info`, `note`, `session_end`; обратимое экранирование `text` по FR-22 (печатные ASCII как есть, `<` как `<x3C>`, именованные управляющие как `<STX>`, остальные байты как `<xHH>`) с обратной функцией и proptest; писатель отдельной задачей `tokio` с неограниченным каналом и групповой фиксацией (`write` → `flush` → `sync_data` на пачку); дописывание `note` в конец файла; читатель с номером строки и допуском обрезанной последней строки. Формат описан в `docs/reference/session-format.md` и JSON Schema `docs/public/schema/bytetap-session-1.schema.json`; решение о писателе — ADR 0001.
- `bytetap-cli verify <файл>` — проверка журнала по вшитой JSON Schema и статистика (события по типам, байты по направлениям, соединения), код выхода ≠ 0 при ошибке; `bytetap-cli note <файл> <текст>` дописывает комментарий инженера (FR-23).
- Синтетический журнал `tests/fixtures/journal/minimal.jsonl` (HL7/MLLP, `ANALYZER`/`LIS`/`PATIENT^TEST`) и тест устойчивости T-4: журнал остаётся валидным после аварийного убийства процесса (M1-AC16, M1-AC7).
- Автоответчик `bytetap-core::responder` (FR-16, FR-18): sans-IO трейт `Responder` (`feed(&[u8], now) -> Vec<Action>`, `finish(now)`, `reset` для COM) и реализации `NoResponder` и `Hl7Mllp`; автомат MLLP собирает сообщения по рамке `0x0B … 0x1C 0x0D` при любом разбиении потока, не теряет мусор вне рамки, ограничивает незакрытую рамку 16 МиБ, при закрытии соединения сообщает о недособранной рамке и хвосте мусора; ACK берёт разделители из `MSH-1`/`MSH-2`, меняет местами `MSH-3/4` и `MSH-5/6`, копирует `MSH-11`/`MSH-12` (пустой `MSH-11` → `P`), выдаёт новый `MSH-10` из общего на сессию счётчика (не длиннее 20 знаков), возвращает `MSA|AA|<MSH-10>`, на неразбираемое сообщение — `MSA|AE` с извлекаемым `MSH-10` на разделителях того `MSH` (иначе `|^~\&` с экранированием), кодировка ACK — ASCII, входящий ACK не подтверждается, чтобы не завести петлю ACK↔ACK. Запросы (`QRY^Q02`) подтверждаются только ACK, без `DSR` (M1-AC8, M1-AC9, M1-AC10, T-1). Поведение описано в `docs/reference/autoresponder.md`, синтетические фикстуры — в `tests/fixtures/hl7/`.

### Исправлено

- Писатель журнала держит файл под эксклюзивной блокировкой (`File::try_lock`) и в режиме дописывания; `note` отказывается дописываться, пока идёт сессия, и в файл с обрезанным хвостом, чтобы не повредить журнал (FR-23). Заголовок `session` пишется и фиксируется синхронно до запуска задачи; без runtime `Journal::create` отказывает, не создавая файл; занятое имя получает суффикс `-2`…`-99`; момент старта один для `Session::at` и имени файла (FR-19).
- Остановка писателя закрывает канал и дочитывает остаток в последнюю пачку, поэтому каждое принятое событие оказывается в файле; `pending` растёт до отправки; ошибка сериализации одного события не выбрасывает пачку (FR-20, T-4).
- Папка журналов по умолчанию — `<home>/Documents/bytetap`, а не known folder «Документы»: Known Folder Move не уводит журналы с данными пациентов в OneDrive. Добавлена `log_dir_warning` о папке в OneDrive и о сетевом пути (FR-19).
- Обрезанной считается только последняя строка без `\n`, на которой разбор JSON остановился из-за конца ввода; иначе это ошибка разбора. `unescape` принимает только каноническую запись: верхний регистр `<xHH>` и лишь для байтов, которые `escape` так пишет (FR-22).
- Схема журнала: шаблон поля `text`, `$id` на GitHub Pages, формат `host.os` в примере; `bytetap-cli verify` дополнительно проверяет `len` и `text` относительно `b64`, единственность и первое место заголовка `session`, допустимость только `note` после `session_end`, суммы байтов без переполнения.
- `_stress-journal --max-seconds` (по умолчанию 30) завершается штатно, тест устойчивости ловит ранний выход процесса и печатает его stderr.
