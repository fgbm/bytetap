# Тестирование

Документ для участников проекта и владельца: что проверяется автоматически в CI, что проверяется руками на Windows-сборке и как это сделать.

## Автоматические проверки

Один прогон перед сдачей — из корня репозитория:

```bash
npm run check
```

Скрипт последовательно запускает:

- `cargo fmt --all --check` — форматирование;
- `cargo clippy --workspace --all-targets -- -D warnings` — предупреждения как ошибки;
- `cargo test --workspace --no-fail-fast` — тесты ядра, CLI и моста приложения, включая интеграционные на loopback (COM-тест на паре pty помечен `#[ignore]` и запускается отдельно, см. ниже);
- `npm run check --workspace app` — `vue-tsc`;
- `npm run test --workspace app` — vitest (форматирование, HEX, кодировки, кольцевой буфер, виртуализация, страницы журнала, редьюсер сессии, i18n-ключи);
- `node scripts/check-docs-links.mjs` — ссылки навигации сайта.

Отдельно собираются фронтенд и сайт:

```bash
npm run build
npm run docs:build
```

Windows-сборка exe (то же, что делает CI):

```powershell
npm run tauri build -- --no-bundle
```

Готовый файл — `target\release\bytetap.exe`. Тяжёлый нагрузочный тест NFR-5/NFR-6 помечен `#[ignore]` и в обычный прогон не входит.

CI на GitHub Actions повторяет это на Ubuntu и Windows (`ci.yml`), включая `actionlint` и `zizmor`, и складывает `bytetap.exe` в артефакт `bytetap-windows-x64`.

## Ручной смоук v0.1.0 на Windows (UI v2, M2-AC18)

Выполняет владелец на черновике релиза v0.1.0: сборка из артефакта CI или `bytetap.exe` из zip черновика. Интерфейс — UI v2: одна шапка-заголовок окна без системной рамки, три сценария вместо переключателя режимов, служебное в свёрнутом «Дополнительно» и в меню «…» (принципы — в [дизайн-системе](/dev/design)).

Нужно: Windows 10/11 с WebView2, свободный порт 5000, PowerShell для скриптов из разделов «Источник данных» ниже и, для COM, пара виртуальных портов com0com из раздела «COM-порт на Windows». `bytetap-cli` в zip и в артефакте не лежит и источником данных не является: он пишет журнал, но сообщений не присылает.

Подготовка:

- [ ] Взять `bytetap.exe` из артефакта `bytetap-windows-x64` (Actions → нужный run → Artifacts) или из zip черновика; в свойствах exe и в имени архива одна версия v0.1.0, `SHA256SUMS` сходится.
- [ ] Запустить с чистой папкой настроек: окно открывается 1200×800, сжать меньше 720×560 нельзя, ошибок нет.
- [ ] На машине без WebView2 (если такая есть): системное сообщение «Для работы bytetap нужен компонент Microsoft Edge WebView2…», окно не создаётся, программа закрывается сама.

Окно без рамки:

- [ ] Шапка — заголовок окна: тянется мышью за пустое место, двойной клик разворачивает и восстанавливает.
- [ ] Кнопки справа 46×44 во всю высоту шапки: свернуть, развернуть/восстановить (иконка меняется), закрыть; у крестика при наведении красный фон `--bt-window-close` с белой иконкой.
- [ ] Закрытие окна во время записи: сначала останавливается сессия, потом закрывается окно; журнал заканчивается `session_end` — в PowerShell `Get-Content <файл> -Tail 1` показывает `"type":"session_end"`.

Стартовый экран:

- [ ] Вопрос «Как анализатор связан с этим ноутбуком?» и три карточки: анализатор подключается ко мне, я подключаюсь к анализатору, кабель COM-порта; карточка последнего запуска обведена и показывает «последний раз: …».
- [ ] ↑/↓ двигают подсветку по карточкам, Enter открывает выбранную, клик открывает карточку.
- [ ] «Последние записи» — до трёх журналов с именем, анализатором и временем; клик открывает журнал.

Сценарий «Анализатор подключается ко мне» (нужен скрипт HL7 из раздела ниже):

- [ ] Порт, «Автоответ» (по умолчанию «Авто — HL7 или ASTM по первому байту»), крупный адрес вида `192.168.1.10:5000` моно 28px с кнопкой «Скопировать» → «Скопировано»; ниже строка «другая сеть: …», если интерфейсов несколько, и muted-строка про брандмауэр.
- [ ] «Дополнительно»: интерфейс прослушивания, анализатор, комментарий, папка журналов, профили, «NAK на неверную сумму ASTM» (при «Авто» и «ASTM»).
- [ ] «Старт» — Windows спрашивает брандмауэр, ответить «Разрешить для частных сетей» (NFR-4).
- [ ] Запустить скрипт HL7: в шапке «слушаю …:5000 · HL7 (авто)», в ленте `#1 подключился`, фрагмент анализатора с глифами `‹VT›`, `‹CR›`, `‹FS›`, ACK со словом «автоответ», `#1 отключился`.

Сценарий «Я подключаюсь к анализатору»:

- [ ] Пустой «Адрес анализатора» после «Старт» — красная строка 12px под полем «Укажите адрес анализатора», файл журнала не появляется.
- [ ] Старт с недоступным адресом: в шапке сводка «подключено к … · HL7 (авто)», в ленте ошибка подключения, повторы не забивают ленту строкой в секунду, «Стоп» останавливает сразу.

Сценарий «Кабель COM-порта» (нужна пара com0com из раздела ниже):

- [ ] Список портов с описанием, «Обновить список портов» подхватывает порт, созданный уже после открытия формы.
- [ ] «Скорость» (9600 и «другая…») и «Формат» (`8N1`, `7E1`); «Дополнительно»: поток, DTR, RTS.
- [ ] «Старт» — в шапке «COM5 · 9600 8N1», обмен из терминала на втором порту пары идёт в ленту, в терминал приходит `ACK` (`0x06`), а в ленте ответ помечен «автоответ».
- [ ] Старт с портом, выдернутым после обновления списка, — ошибка «Порт COM5 не найден…» под полем, без падения.

Запись (любой из трёх сценариев):

- [ ] В записи одна строка шапки: пилюля «Стоп» с пульсирующей точкой и таймером, сводка режима, счётчики «→ байты ← байты N соед.», меню «…», кнопки окна.
- [ ] «…» → «Комментарий…»: текст появляется строкой в ленте и в заголовке журнала.
- [ ] «…» → «Открыть папку журналов» открывает проводник на папке, «Скопировать путь к журналу» кладёт путь в буфер обмена.
- [ ] «…» → переключение темы: запись не прерывается.
- [ ] «Стоп»: таймер и счётчики исчезают, в ленте «сессия остановлена», файл журнала закрыт.

Лента и трасса:

- [ ] «Текст»/«HEX» переключаются; в HEX по 16 байт в строке, выбор кодировки виден только в «Текст» (по умолчанию CP1251).
- [ ] Кодировки ASCII, CP1251, UTF-8, GBK, Latin-1: кириллица в CP1251 и UTF-8 читается без мусора.
- [ ] Управляющие символы — глифы `‹CR›`, `‹STX›` цветом `ctrl` 11px без фона; в HEX они же выделены только цветом, без плашек.
- [ ] Второе соединение: сверху появляется фильтр «Соединение» («все» и номера), выбор фильтрует ленту.
- [ ] Прокрутка вверх останавливает догон, внизу справа появляется тёмная таблетка «↓ N новых», клик возвращает вниз и включает догон.
- [ ] Трасса над лентой: две дорожки «анализатор → ЛИС» и «ЛИС → анализатор», импульсы по длине фрагментов, глифы `→`/`←`.

Автоответ:

- [ ] «Авто» на HL7: ACK в ленте помечен «автоответ», в шапке «HL7 (авто)».
- [ ] «Авто» на ASTM (скрипт ниже): на `ENQ` приходит `ACK`, на кадр — `ACK`, в шапке «ASTM (авто)».
- [ ] «HL7/MLLP» и «ASTM E1381» вручную: на чужой протокол ответа нет, байты пишутся, в шапке профиль назван без «(авто)».

Просмотр журнала:

- [ ] «Журналы» → «Открыть журнал…», выбрать записанный файл: в шапке имя файла, анализатор, длительность; под шапкой строка «Может содержать персональные данные пациентов — не пересылайте без обезличивания.»
- [ ] Трасса стала картой всей сессии в тонкой рамке; клик по карте переводит ленту к месту, рамка видимой области двигается при прокрутке ленты.
- [ ] «Комментарий» дописывает строку `note`: она видна в конце ленты и в метаданных; после закрытия и повторного открытия файла на месте.
- [ ] «Закрыть журнал» (×) возвращает стартовый экран.
- [ ] Во время записи «Открыть журнал…» в меню «Журналы» недоступна.

Отказ журнала:

- [ ] Начать запись в папку на флешке и вынуть флешку (или занять диск так, чтобы места не осталось): под шапкой появляется строка «Запись в журнал прервана: …» с действиями «Выбрать другую папку» и «Открыть записанное», без модального окна.
- [ ] «Старт» с недоступной папкой журналов: красная строка «Не удалось писать в папку журналов …» под полем папки в «Дополнительно», файл журнала не создаётся.
- [ ] «Выбрать другую папку» меняет папку в настройках и убирает строку; следующий «Старт» пишет в новую папку.
- [ ] «Открыть записанное» открывает журнал с тем, что успело записаться (если путь неизвестен — папку журналов).

Тема, профили, настройки:

- [ ] Тема по умолчанию системная; переключатель Sun/Moon показывает, в какую тему переведёт, выбор сохраняется после перезапуска.
- [ ] Профиль: «Сохранить», выбрать в списке (поля меняются), «Удалить»; после перезапуска профили на месте.
- [ ] Последние настройки (порт, адрес, порт и скорость COM, анализатор, комментарий, папка, сценарий, вид ленты и кодировка) восстанавливаются после перезапуска.

## COM-порт: `socat` на Linux (T-3, M3-AC11)

Тест `crates/bytetap-core/tests/serial.rs` помечен `#[ignore = "requires socat"]`: в обычном `cargo test` его нет, поэтому на машине без `socat` он не падает и не зеленеет молча. Запускается он отдельной командой:

```bash
sudo apt-get install -y socat
cargo test -p bytetap-core --test serial -- --ignored
```

CI на ubuntu ставит `socat` и запускает ровно эту команду с `BYTETAP_REQUIRE_SOCAT=1`. С этой переменной отсутствие `socat` или его отказ — падение теста: COM-режим в CI не должен остаться непроверенным. Без переменной (локальный прогон) тест при отсутствии `socat` печатает «тест пропущен: `socat` не найден» и завершается: пропуск виден в выводе.

Если `socat` есть, тест открывает первый pty как COM-порт, пишет во второй `ENQ` и кадр ASTM E1381 (номер кадра `'1'` — первый после `ENQ`), ждёт `ACK` и проверяет журнал: `peer` — имя порта, `local` пуст, оба направления записаны, ответы `synthetic`, событий `info` и `error` нет — нумерация кадров верная. На pty DTR/RTS не выставляются (у псевдотерминала нет управляющих линий): тест передаёт `--dtr off --rts off`, а `ENOTTY` от этих линий программа не считает ошибкой.

## COM-порт на Windows: ручной сценарий com0com (T-3)

Автоматического теста на Windows нет: пара виртуальных портов ставится драйвером, а его установка в CI не автоматизируется. Проверка выполняется вручную на сборке из CI. `bytetap-cli` в артефакт не входит: соберите его из исходников (`cargo build --release -p bytetap-cli`, файл `target\release\bytetap-cli.exe`) или пройдите те же шаги в интерфейсе — сценарий «Кабель COM-порта» в чек-листе выше.

- [ ] Установить [com0com](https://sourceforge.net/projects/com0com/) и создать пару портов, например `COM5` ↔ `COM6` (в свежих сборках com0com номера задаются в Setup).
- [ ] Запустить `bytetap-cli ports`: в списке есть оба порта, у пары com0com описание — имя порта.
- [ ] Запустить `bytetap-cli capture --serial COM5 --baud 9600 --format 8N1 --responder astm`.
- [ ] Открыть `COM6` терминалом (PuTTY, RealTerm) с теми же 9600 8N1.
- [ ] Отправить `ENQ` (`0x05`): в терминал приходит `ACK` (`0x06`), в ленте `capture` — фрагмент анализатора и синтетический ответ.
- [ ] Отправить кадр `STX 1H|\^&… ETX <сумма> CR LF` (номер кадра — ASCII `1`, первый после `ENQ`) с верной суммой: приходит `ACK`; с неверной — по умолчанию тоже `ACK` и `error` в журнале, с `--astm-nak` — `NAK` (`0x15`).
- [ ] Нажать «Стоп»: соединение закрывается событием `close`, журнал заканчивается `session_end`.
- [ ] Отключить пару com0com во время записи: в журнале `close` и `error`, сессия продолжает работать; после включения пары порт переоткрывается сам, в журнале новое `open` с следующим `conn`.
- [ ] Проверить `bytetap-cli verify` на получившемся журнале: ошибок нет.

## Источник данных: HL7 по TCP (PowerShell)

Если под рукой нет анализатора и `bytetap-testkit` (он собирается из исходников), синтетическое сообщение шлёт PowerShell той же машины. Нужен запущенный «Анализатор подключается ко мне» на порту 5000 и автоответ «HL7/MLLP» или «Авто»; скрипт печатает ACK.

```powershell
$client = [System.Net.Sockets.TcpClient]::new("127.0.0.1", 5000)
$client.ReceiveTimeout = 5000
$stream = $client.GetStream()
$msh = "MSH|^~\&|ANALYZER|LAB|LIS||20261019101500||ORU^R01|MSG0001|P|2.3.1"
$pidSegment = "PID|1||000001||PATIENT^TEST"
# Рамка MLLP: 0x0B, сообщение с CR, 0x1C, CR
$msg = [Text.Encoding]::ASCII.GetBytes("$([char]11)$msh`r$pidSegment`r$([char]28)`r")
$stream.Write($msg, 0, $msg.Length)
$buffer = New-Object byte[] 4096
$read = $stream.Read($buffer, 0, $buffer.Length)
[Text.Encoding]::ASCII.GetString($buffer, 0, $read)
$client.Close()
```

В ленте появятся `#1 подключился`, фрагмент анализатора с глифами `‹VT›`, `‹CR›`, `‹FS›` и ответ со словом «автоответ»; после закрытия соединения — `#1 отключился`. Для профиля «Без ответов» ACK не придёт — это ожидаемо.

## Источник данных: ASTM E1381 по TCP (PowerShell)

ASTM идёт тем же портом 5000: профиль «Авто» узнаёт его по первому байту `ENQ` (`0x05`). Нужен автоответ «ASTM E1381» или «Авто». Скрипт проводит полный обмен — `ENQ`, кадр записи `'1'` с верной суммой, `EOT` — и читает оба `ACK`.

```powershell
$client = [System.Net.Sockets.TcpClient]::new("127.0.0.1", 5000)
$client.ReceiveTimeout = 5000
$stream = $client.GetStream()

# Запись: три сегмента, каждый заканчивается CR
$segments = "H|\^&|||ANALYZER^1|||||||||P|1`rP|1||PATIENT^TEST`rL|1|N`r"
# Сумма считается по байтам от номера кадра до ETX включительно, по модулю 256
$body = [Text.Encoding]::ASCII.GetBytes("1" + $segments + [char]3)
$sum = 0
foreach ($b in $body) { $sum = ($sum + $b) % 256 }

$stream.Write([byte[]]@(0x05), 0, 1); $null = $stream.ReadByte()   # ENQ → ACK
$stream.Write([byte[]]@(0x02), 0, 1)                                 # STX
$stream.Write($body, 0, $body.Length)                               # 1 … ETX
$checksum = [Text.Encoding]::ASCII.GetBytes(("{0:X2}" -f $sum) + "`r`n")
$stream.Write($checksum, 0, $checksum.Length)                      # сумма 2C, CR LF
$null = $stream.ReadByte()                                          # ACK на кадр
$stream.Write([byte[]]@(0x04), 0, 1)                                 # EOT, ответа нет
$client.Close()
```

Для этих сегментов сумма — `2C`: `0x31 + 0x48 … + 0x0D + 0x03 = 0x12C`, по модулю 256 — `0x2C`. Если править текст записи, сумму нужно пересчитать — иначе кадр подтвердится, но в журнале появится `error` о неверной сумме (а с «NAK на неверную сумму» ответ будет `NAK`, `0x15`).
