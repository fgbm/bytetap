# M3 — TCP-клиент, ASTM, «Авто», COM-порт

Цель этапа — покрыть типовые сетевые и COM-анализаторы: bytetap сам подключается к анализатору-серверу по TCP, работает вместо ЛИС через COM-порт, понимает ASTM E1381 и определяет протокол по первому байту. После M3 выпускается v0.1.0 (MVP): TCP-сервер, TCP-клиент, COM, автоответчики MLLP, ASTM и «Авто», журнал и интерфейс.

## Макет

Форма COM-порта — вкладка «1б · COM-порт» [макета главного экрана](/mockups/m2-main.html), утверждённого владельцем: режим «COM-порт», порт с понятным описанием и кнопкой обновления, «Скорость · формат» (9600 и `8N1`), автоответ, свёрнутая строка «Дополнительно: управление потоком · DTR · RTS». Формы TCP-клиента в макете нет: она повторяет форму TCP-сервера и добавляет адрес анализатора, порт и интервал переподключения (5 с). Чипы идущей записи получают новый режим и профиль автоответа. Токены, иконки и шрифты — те же, что в M2: `design/tokens.css`, `@lucide/vue`, IBM Plex.

## Решения этапа

- Сессия перестаёт быть «TCP-сервером»: она получает соединения из источника, а транспорт — `AsyncRead + AsyncWrite`. TCP-клиент, COM и будущие режимы добавляются источником, а не второй копией сессии, поэтому журнал, автоответчик и остановка остаются одни.
- «Авто» — обёртка над готовыми профилями: решение принимается один раз на соединение по первому байту и дальше не пересматривается. Нераспознанный протокол не мешает записи: байты идут в журнал, ответов нет.
- ASTM подтверждается только на транспортном уровне (FR-18): ENQ и кадры получают ACK/NAK, запросы анализатора не разбираются и ответов не порождают.
- COM: соединение — одно открытие порта. При ошибке порта (нет порта, выдернут адаптер, ошибка чтения) пишется `close` и `error`, порт переоткрывается с интервалом, сессия продолжается (NFR-5).
- Крейт COM выбирается в ADR 0002 на шаге 4: от него зависят и список портов с VID/PID (FR-12), и отмена чтения при остановке. Сессия видит только транспорт, поэтому решение не влияет на её код.
- Режим COM пишется в журнал как `serial` (имя файла `bytetap-…-serial.jsonl`): значение `com_server` из M1 переименовывается, `com_monitor` и `com_tcp` остаются для M5 и FR-13.
- «Авто» — профиль автоответа по умолчанию в интерфейсе. В CLI `--responder` остаётся обязательным, чтобы журнал не зависел от умолчания версии (M1-AC15).
- Неудачные подключения и ошибки порта схлопываются так же, как ошибки `accept` в M1: одно `error`, затем `info` о повторах и о восстановлении, иначе недоступный анализатор забивает журнал строкой в секунду.

## Архитектура

- `transport` получает трейт источника: `ConnectionSource::next(&mut self) -> Next`, где `Next::{Connected(Connection), Retry { error: io::Error, after: Duration }}`; `Connection` отдаёт транспорт `Box<dyn Transport>` (`AsyncRead + AsyncWrite + Unpin + Send`) и два строковых поля для событий `open`: `peer` и `local`. Источник не нумерует соединения, не знает про журнал и автоответчик — это по-прежнему делает сессия.
- Повтор подключения — внутри цикла сессии, а не внутри источника: источник говорит «через сколько повторить», сессия пишет `error`/`info` и ждёт в `select!` вместе с остановкой и отказом журнала. Так недоступный анализатор не мешает «Стоп», а пауза проверяется тестом без реального ожидания (`tokio::time::pause`).
- `serve` работает с `&mut dyn Transport`: чтение, запись ответа, счётчики, `data`, `finish` автоответчика и `close` — один код для TCP-сервера, TCP-клиента и COM. Транспорт умеет `read`, `write` (сколько байт принято), `shutdown`; TCP-обёртка сохраняет `TCP_NODELAY` (NFR-6).
- Источники: `TcpServer` (M1), `TcpClient { addr, reconnect }`, `Serial { settings, reconnect }`. Для TCP-клиента `open` пишется только после успешного подключения, `peer` — адрес анализатора, `close` — с причиной `eof`/`reset`. Для COM `open` — каждое открытие порта, `peer` — имя порта (`COM5`), `local` — пустая строка: адресов у порта нет, правило записывается в `session-format.md`.
- `Responder` получает метод `poll_timeout(&mut self, now: Now) -> Option<Duration>` с реализацией по умолчанию `None`: сессия держит срок в `select!` и по истечении будит автомат пустым `feed(&[], now)`. Нужен ASTM, чтобы недособранный кадр не ждал следующего соединения; поведение MLLP и «Без ответов» не меняется.
- ASTM E1381 (`responder::astm`, sans-IO): `ENQ` (`0x05`) → `ACK` (`0x06`); кадр `STX FN text ETX|ETB C1 C2 CR LF` → `ACK`; `EOT` (`0x04`) → ожидание; `NAK` (`0x15`) только по настройке. Сумма — по модулю 256 от `FN` до `ETX`/`ETB` включительно, на отправку две hex-цифры верхнего регистра, на приём допускается нижний. Номер кадра `FN` — 0–7 циклически, нарушение последовательности — событие `info`, кадр всё равно подтверждается. Мусор вне кадра не ломает автомат; недособранный кадр по `finish` попадает в журнал событием, а не теряется молча.
- «Авто» (`responder::auto`): обёртка держит необязательный выбранный профиль и до решения копит только первый байт; `0x0B` → `Hl7Mllp`, `0x05` → `AstmE1381`, иначе `NoResponder` и `info` с предупреждением. Фрагмент целиком передаётся выбранному автомату, поэтому первый байт не теряется и порядок сохраняется.
- COM: настройки FR-11 в одной структуре (`baud`, `data_bits`, `parity`, `stop_bits`, `flow`, `dtr`, `rts`) с проверкой до создания журнала: скорость 1…4 000 000 (типовые 300–115200 в списке), 7/8 бит, чётность none/even/odd/mark/space, стоп 1/2, поток none/RTS-CTS/XON-XOFF, начальные DTR и RTS. Отказ ОС или неподдерживаемое сочетание — ошибка старта с понятным текстом, файл журнала не создаётся.
- Список портов FR-12: перечисление блокирующее, поэтому в мосте идёт через `spawn_blocking`; описание собирается из USB VID/PID, продукта и производителя — «USB-SERIAL CH340 (COM5)», для не-USB портов остаётся имя; сортировка по номеру (`COM2` раньше `COM10`), кнопка обновления перезапрашивает список.
- Журнал: `mode` — `tcp_client` или `serial`; `settings` — фактические параметры режима (`connect` и `reconnect_sec`; `port`, `baud`, `format`, `flow`, `dtr`, `rts`); `autoresponder` — фактический профиль. `info` и `error` получают необязательное поле `code` (список в `session-format.md`), по нему интерфейс берёт русскую строку из i18n, а `message` остаётся английским для журнала и поиска.
- Автоответ на COM и в TCP-клиенте — тот же код, что в M1: `apply` отправляет ответ до записи в журнал, ответы идут с `dir: lis_to_analyzer` и `synthetic: true` (FR-4).

## Контракт моста

TypeScript-типы лежат в `app/src/api/types.ts`; команды Tauri называются так же, в snake_case. Поля, добавленные в M3:

- `SessionConfig = {mode: 'tcp_server' | 'tcp_client' | 'serial', listenHost?: string, listenPort?: number, connectHost?: string, connectPort?: number, reconnectSec?: number, serial?: {port: string, baud: number, dataBits: 7 | 8, parity: 'none' | 'even' | 'odd' | 'mark' | 'space', stopBits: 1 | 2, flow: 'none' | 'rtscts' | 'xonxoff', dtr: boolean, rts: boolean}, responder: 'auto' | 'hl7' | 'astm' | 'none', astmNakOnBadChecksum: boolean, analyzer: string, note: string, logDir: string}` — поля чужого режима необязательны, лишние отвергаются ядром до создания журнала; `reconnectSec` по умолчанию 5, `dtr` и `rts` — включены, `astmNakOnBadChecksum` — выключен.
- `list_serial_ports(): {name: string, description: string}[]` — порты для формы COM; перечисление не блокирует поток окна.
- `StartInfo.localAddr` — фактический адрес слушателя для TCP-сервера, локальный адрес сокета для TCP-клиента, имя порта для COM; строка состояния показывает то, что есть.
- `FeedEvent.open` для COM: `peer` — имя порта, `local` — пустая строка. `info` и `error` получают необязательный `code`.
- Ошибки команд к прежним кодам (`port_in_use`, `address_unavailable`, `permission_denied`, `log_dir`, `already_running`, `journal`, `io`) добавляют `port_not_found`, `port_busy`, `port_settings`, `address_invalid`, `serial`.
- `stop_session`, `SessionSummary`, `add_session_note`, `open_journal`, `read_journal` не меняются.

## Критерии приёмки

- [ ] M3-AC1 (FR-2). TCP-клиент: `capture --connect HOST:PORT [--reconnect-sec N]` подключается к анализатору-серверу; старт не требует доступного анализатора (сессия стартует, первая неудачная попытка — `error`, дальше повтор через интервал, по умолчанию 5 с, `--reconnect-sec` 0…3600). При закрытии или ошибке соединения — `close` и новое подключение; каждое подключение получает следующий `conn`, `open` пишется только после успешного подключения, `peer` и `local` — адрес анализатора и локальный адрес сокета. Повторяющиеся ошибки подключения схлопываются: одно `error`, затем `info` о повторах и о восстановлении. Тест на loopback: анализатор-сервер принимает соединение, обрывает его, принимает второе — два `open` с разными `conn`, `close` с `by: analyzer`, пауза между попытками не меньше заданной и не растягивает «Стоп».
- [ ] M3-AC2 (FR-9). COM «вместо ЛИС»: `capture --serial COM5 --baud 9600 --format 8N1` открывает порт и ведёт обмен как TCP-сервер — те же события `open`, `data`, `close`, `error`, `info`, тот же автоответчик, ответы с `synthetic: true`, `conn` — номер открытия порта, сквозной по сессии. Ошибка порта (нет порта, выдернут адаптер, ошибка чтения) закрывает соединение событиями `close` и `error`, порт переоткрывается с интервалом, сессия продолжается. `open` для COM: `peer` — имя порта, `local` — пустая строка, правило записано в `session-format.md`.
- [ ] M3-AC3 (FR-11). Настройки порта: скорость 300–115200 и произвольное значение (принимается 1…4 000 000), биты данных 7/8, чётность none/even/odd/mark/space, стоп-биты 1/2, управление потоком none/RTS-CTS/XON-XOFF, начальные DTR и RTS (вкл/выкл). `--format` разбирается как `<биты><чётность><стоп>` (`8N1`, `7E2`, `8M1`) и форматируется обратно, в том числе для чипа идущей записи. Неподдерживаемое сочетание и отказ ОС — ошибка старта по-русски до создания файла журнала; фактические значения попадают в `settings` заголовка.
- [ ] M3-AC4 (FR-12). `bytetap-cli ports` и `list_serial_ports(): {name, description}[]` дают список доступных портов с понятным описанием: для USB-адаптера — продукт и производитель из VID/PID, например «USB-SERIAL CH340 (COM5)», иначе имя порта; сортировка по номеру (`COM2` раньше `COM10`). Кнопка обновления в форме COM перезапрашивает список. Порт, пропавший между обновлением и стартом, даёт ошибку `port_not_found` у поля, а не панику. Тест: сборка описания из фикстур USB и не-USB порта, пустой список на машине без портов не ошибка.
- [ ] M3-AC5 (FR-14). Все четыре профиля доступны в ядре, CLI и интерфейсе: `hl7_mllp`, `astm_e1381`, `auto`, `none`; выбранный профиль пишется в `autoresponder` заголовка журнала; неизвестное значение отвергается до создания файла. Unit-тест: каждый профиль создаёт сессию и пишет в заголовок своё значение.
- [ ] M3-AC6 (FR-15). «Авто»: решение по первому байту первого фрагмента соединения — `0x0B` → HL7/MLLP, `0x05` → ASTM E1381; иначе «Без ответов», `info` с кодом `protocol_undetected` и предупреждение в ленте «Протокол не определён — ответы отключены для этого соединения. Запись идёт.» (строка из макета вкладки «Ошибки», через i18n; сообщение журнала — английское). Решение принимается один раз на соединение, для COM — на открытие порта; первый байт не теряется: выбранный автомат получает фрагмент целиком. Пока протокол не определён, байты пишутся в журнал, ответов нет. Unit-тесты: все три исхода, первый фрагмент из одного байта, первый байт отдельным фрагментом, повторное определение не происходит.
- [ ] M3-AC7 (FR-17). ASTM E1381 sans-IO: `ENQ` → `ACK`, кадр `STX FN text ETX|ETB C1 C2 CR LF` → `ACK`, `EOT` → ожидание. Контрольная сумма — по модулю 256 от `FN` до `ETX`/`ETB` включительно, на отправку две hex-цифры верхнего регистра, на приём допускается нижний. При неверной сумме по умолчанию отправляется `ACK` и пишется `error` (цель — получить данные); настройка «NAK на неверную сумму» меняет ответ на `NAK` (`0x15`) и тоже пишет `error`. `FN` 0–7 циклически, нарушение последовательности — `info`, кадр подтверждается. Мусор вне кадра не ломает автомат, недособранный кадр по `finish` попадает в журнал событием.
- [ ] M3-AC8 (FR-18). ASTM-запросы (записи `Q`) подтверждаются только транспортно: `ACK` на кадр, никаких ответных кадров и `synthetic`-данных, кроме `ACK`/`NAK`. Запрос виден в журнале обычным `data` с `dir: analyzer_to_lis`. Тест: эмулятор шлёт `Q|…`, получает `ACK`, других байт не получает.
- [ ] M3-AC9 (T-1). Unit-тесты ASTM: все переходы автомата (`ENQ`, кадр с `ETX`, кадр с `ETB`, `EOT`, мусор, несколько кадров в одном фрагменте, кадр, разрезанный на любое число фрагментов); контрольная сумма — верная, неверная, нижний регистр, границы 0x00/0xFF; `FN` 0–7 и переход 7→0; обе настройки NAK; таймаут через `poll_timeout`. Proptest: «поток целиком = тот же поток по фрагментам» (одинаковые ответы и события) и «автомат не паникует на произвольных байтах при произвольной нарезке».
- [ ] M3-AC10 (T-2). Эмулятор анализатора ASTM в `bytetap-testkit`: `ENQ`, кадры (несколько в соединении), `EOT`, режимы «целиком», «побайтно», «случайная нарезка», «неверная сумма», ожидание `ACK` с таймаутом и падением теста на неверный ответ. Интеграционные тесты на loopback: ASTM ↔ сессия в режимах TCP-сервер и TCP-клиент; склейка `b64` по `analyzer_to_lis` побайтно равна отправленному, каждый кадр подтверждён `ACK` с `synthetic: true`, `session_end` содержит число соединений и байты. TCP-клиент: эмулятор работает сервером, рвёт соединение и принимает второе — два `open` с разными `conn`, `close` с `by: analyzer`, интервал переподключения выдержан.
- [ ] M3-AC11 (T-3). COM на Linux: автоматический тест через пару pty от `socat -d -d pty,raw,echo=0 pty,raw,echo=0` (`#[cfg(unix)]`, в CI на ubuntu-latest ставится `apt-get install socat`); тест открывает один конец портом, пишет во второй `ENQ` и кадр ASTM, проверяет `ACK` и запись обоих направлений в журнал; на pty DTR/RTS не выставляются (pty их не поддерживает). При отсутствии `socat` тест помечается пропущенным с явным сообщением, а не молча зелёным. Ручной сценарий com0com на Windows — чек-лист в `docs/dev/testing.md`. ADR 0002 фиксирует выбор крейта (`tokio-serial` или `serialport` с блокирующим потоком) и его последствия.
- [ ] M3-AC12. Источник соединений: сессия работает с трейтом источника и транспортом `AsyncRead + AsyncWrite`, `serve` не знает, TCP это или COM, нумерация `conn` сквозная; один набор проверок (`open`, `data`, `close`, остановка, отказ журнала) проходит для TCP-сервера, TCP-клиента и COM; `bytetap-core` по-прежнему без tauri.
- [ ] M3-AC13. Интерфейс: режимы «TCP-клиент» и «COM-порт» активны, «Прокси» и «Прослушка COM» остаются неактивными с пометками v0.2 и v0.3. Форма TCP-клиента — адрес анализатора, порт, интервал переподключения (5 с). Форма COM — по макету «1б · COM-порт»: порт с описанием и кнопкой обновления, «Скорость · формат» (9600 и `8N1`), автоответ, свёрнутая строка «Дополнительно: управление потоком … · DTR … · RTS …». Ошибки полей (порт не выбран, адрес пуст, порт вне 1–65535) — у поля по-русски; во время записи настройки сворачиваются в чипы с новым режимом и профилем автоответа. Vitest: редьюсер настроек, форматирование и разбор `8N1`, чипы режимов.
- [ ] M3-AC14. «Авто» по умолчанию в форме автоответа, для всех режимов; выбранный профиль запоминается между запусками (FR-30) и восстанавливается из профиля. В CLI `--responder` остаётся обязательным (`auto|hl7|astm|none`), чтобы умолчание версии не меняло журнал незаметно.
- [ ] M3-AC15. CLI: `capture --connect HOST:PORT [--reconnect-sec N]`, `capture --serial COM5 --baud 9600 --format 8N1 [--flow none|rtscts|xonxoff] [--dtr on|off] [--rts on|off]`, `--responder auto|hl7|astm|none`; ровно один из `--listen`, `--connect`, `--serial` обязателен, иначе clap выдаёт понятную ошибку; `bytetap-cli ports` печатает список портов; параметры описаны в `--help` и `guide/cli.md`.
- [ ] M3-AC16. Журнал: имя файла `bytetap-<YYYYMMDD-HHMMSS>-tcp_client.jsonl` и `…-serial.jsonl`; `mode` для COM — `serial`; `settings` содержит фактические параметры режима; `autoresponder` — фактический профиль; `info` и `error` несут необязательный `code`. `bytetap-cli verify` проверяет такие журналы, `docs/reference/session-format.md` и JSON Schema обновлены (значения `mode`, поле `code`, правило пустого `local` для COM), строки ядра проходят валидацию по схеме в тесте.
- [ ] M3-AC17. CI: `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test` (включая тест на pty), `vue-tsc`, vitest, сборка фронтенда, `npm run docs:build` — зелёные на ubuntu и windows; Windows-сборка exe в артефакт; zizmor и actionlint без замечаний.
- [ ] M3-AC18. Документация: `reference/autoresponder.md` — ASTM E1381 (переходы, сумма, NAK-настройка, таймаут) и «Авто» (определение, предупреждение); `guide/modes.md` — TCP-клиент, COM, нуль-модемный кабель и что указать на анализаторе; `guide/cli.md` — новые команды и `ports`; `docs/dev/testing.md` — com0com и `socat`; ADR 0002; `CHANGELOG.md` дополнен; сайт собирается без битых ссылок.

## Вне рамок

- Прокси TCP (FR-5…FR-8) — этап M4.
- Прослушка двух COM-портов (FR-10) — этап M5.
- Смешанный режим «COM ↔ TCP» (FR-13) — после v0.3.
- Ответы на запросы анализатора: `QRY` → `DSR`, ASTM query (FR-18) — вне первой версии.
- Экспорт в pcapng и разбор сообщений до полей.
