# U1 — нативный интерфейс (egui)

Цель этапа — паритет с UI v2 Tauri-версии и выпуск v0.2.0 без WebView2: тот же интерфейс и те же функции, что в v0.1.0, но приложение — один exe на egui, eframe и wgpu, который запускается на машинах со старым или отсутствующим WebView2. Решение и его последствия — [ADR 0003](/dev/adr/0003-native-ui). Функции ядра, формат журнала и CLI не меняются.

## Эталон

- Визуал и поведение — UI v2 Tauri-версии: раздел «UI v2» [этапа M3](/dev/stages/M3), код `app/src/**` в `main`, снимки `/tmp/opencode/ui-v2/` (сценарии, шаги трёх режимов, запись, ASTM, HEX, прокрутка), [дизайн-система](/dev/design) и ручной смоук в [тестировании](/dev/testing).
- Техника — прототип в ветке `proto/egui` (crate `bytetap-egui`): wgpu на DX12 с WARP, шрифты IBM Plex из TTF, иконки Lucide через resvg, лента на `show_rows`, снимки `egui_kittest`.
- Отступления от UI v2, которых требует egui (ADR 0003): текст без ClearType смягчается кеглем, копирование из ленты — через контекстное меню строки. Остальное — как в Tauri-версии; каждое новое отступление согласует владелец.

## Решения этапа

- Работа идёт в ветке `native-ui`; `main` остаётся на Tauri и получает исправления до паритета, исправления UI v2 из `main` переносятся в U1.
- Crate приложения — `crates/bytetap-app` (bin `bytetap`, exe `bytetap.exe`). Он зависит от `bytetap-core` напрямую: управление — вызовы `bytetap-core::session`, события — подписка `tokio::sync::broadcast` в кольцевой буфер интерфейса на 10 000 фрагментов. Мост Tauri, команды и `Channel` не переносятся.
- Runtime `tokio` живёт в отдельном потоке приложения; поток окна никогда не ждёт ввод-вывод: долгие операции (список портов, индекс журнала, выбор папки) возвращают результат в интерфейс через канал и `request_repaint`.
- Перерисовка — только по событию: в простое кадров нет; во время записи `request_repaint` вызывается не чаще ~30 раз в секунду, сколько бы фрагментов ни пришло.
- Токены остаются в `design/tokens.css` — единый источник для сайта документации и приложения; `build.rs` генерирует из CSS-переменных Rust-константы для светлой и тёмной темы. Ручных копий цветов в Rust нет.
- Логика моста, не зависящая от Tauri (`list_recent_journals`, индекс журнала из `app/src-tauri/src/journal.rs`, `diag.rs`, проверка папки журналов, добавление `note`), переносится в ядро, если она нужна CLI, иначе в crate приложения, вместе с её тестами.
- Настройки и профили — JSON в `%APPDATA%\bytetap` (на Linux — каталог конфигурации пользователя); испорченный файл копируется рядом как `settings.corrupt-<дата>.json`, приложение стартует с умолчаниями и показывает предупреждение — как в Tauri-версии.
- Один экземпляр приложения не обязателен: два окна с разными папками журналов допустимы, как и в v0.1.0.

## Шаги

Каждый шаг — отдельная задача реализации и отдельный цикл ревью.

- [x] Шаг 1. Оболочка: crate `crates/bytetap-app` (bin `bytetap`, `windows_subsystem = "windows"`), eframe и wgpu (DX12, WARP без драйвера), окно без рамки и шапка с кнопками окна, перетаскиванием и ресайзом за края, тема из `design/tokens.css` (`build.rs`), встроенные шрифты Plex и иконки Lucide, i18n (ru) на простом модуле или `rust-i18n`, настройки и профили (JSON в `%APPDATA%\bytetap`, порча → копия и предупреждение), журнал запуска и panic hook (перенос `app/src-tauri/src/diag.rs`).
- [ ] Шаг 2. Сценарии и шаги трёх режимов: карточки сценариев, последние записи (перенос `list_recent_journals`), формы TCP-сервера, TCP-клиента и COM с валидацией, список интерфейсов (`if-addrs`) и COM-портов (ядро), выбор папки (`rfd`), «Дополнительно», профили, ошибки у полей по кодам ошибок старта.
- [ ] Шаг 3. Запись: прямая интеграция с `bytetap-core::session` (поток событий через `broadcast` → кольцевой буфер 10 000, `request_repaint` с ограничением частоты), шапка (Стоп, таймер, сводка режима, счётчики, меню «…»), трасса, лента «Текст»/«HEX» с кодировками (`encoding_rs`), фильтр соединений, «↓ N новых», комментарий, отказ журнала, закрытие окна во время записи → штатная остановка.
- [ ] Шаг 4. Просмотр журнала: индекс, страницы, плотность, `firstEvent` и длины фрагментов (перенос из `app/src-tauri/src/journal.rs` в ядро или crate приложения), карта сессии с переходом, комментарий, строка о персональных данных.
- [ ] Шаг 5. Качество и выпуск: AccessKit (роль и подпись у всех своих виджетов, порядок Tab), DPI 100/125/150 %, ввод кириллицы, производительность (CPU в простое ~0, ограничение перерисовки во время записи), снимочные тесты `egui_kittest` всех экранов в обеих темах, CI (смоук exe на `windows-latest` с проверкой «интерфейс готов» в журнале запуска), удаление `app/` (Tauri и Vue), npm workspace `app`, jobs `frontend` и `windows-app` Tauri, перевод `release.yml` на новый exe, документация (guide со свежими снимками, `architecture.md`, `design.md`), `CHANGELOG.md`, v0.2.0.

## Критерии приёмки

Шаг 1 — оболочка:

- [x] U1-AC1 (NFR-2, NFR-3). `cargo build --release -p bytetap-app` даёт `bytetap.exe`, который запускается двойным щелчком без консольного окна; рядом не нужно ни одного файла, в зависимостях exe (`dumpbin /dependents`) только системные DLL Windows — нет WebView2Loader, .NET и VC++ Redistributable.
- [x] U1-AC2 (NFR-3). Отрисовка — wgpu на DX12; при отсутствии аппаратного адаптера используется WARP: на виртуальной машине без GPU (или с `WGPU_ADAPTER_NAME`/принудительным WARP) окно открывается и работает, в журнале запуска записан выбранный адаптер.
- [ ] U1-AC3 (FR-25). Окно без системной рамки 1200×800, минимум 720×560; шапка — заголовок окна: перетаскивание за пустое место, двойной клик разворачивает и восстанавливает, ресайз за края и углы; кнопки 46×44 «свернуть», «развернуть/восстановить» (иконка меняется), «закрыть» с красным фоном при наведении — как в UI v2.
- [x] U1-AC4. Цвета, радиусы и размеры обеих тем — Rust-константы, сгенерированные `build.rs` из `design/tokens.css`; тест сверяет набор переменных CSS и констант, ручных копий цветов в коде нет. Тема по умолчанию системная, переключатель Sun/Moon, выбор сохраняется.
- [x] U1-AC5. Шрифты IBM Plex Sans и Plex Mono и используемые иконки Lucide встроены в exe; кириллица, глифы стрелок и `‹CR›` отображаются без «тофу».
- [x] U1-AC6 (FR-31). Все строки интерфейса — через модуль i18n с каталогом `ru`; в коде экранов нет русских литералов (проверка тестом или линтом); ключи совпадают с каталогом, отсутствующий ключ — ошибка теста. Добавление `en` — новый каталог без правки экранов.
- [x] U1-AC7 (FR-30). Последние настройки и профили хранятся в `%APPDATA%\bytetap` (JSON); испорченный файл копируется в `settings.corrupt-<дата>.json`, приложение стартует с умолчаниями и показывает предупреждение. Unit-тесты: чтение, запись, порча, миграция отсутствующих полей.
- [x] U1-AC8 (NFR-3). Журнал запуска и panic hook перенесены из `diag.rs`: версия, ОС, адаптер wgpu, «интерфейс готов» после первого кадра; паника пишется в журнал запуска и показывает системное сообщение с путём к нему, процесс не закрывается молча.

Шаг 2 — сценарии и формы:

- [ ] U1-AC9 (FR-25). Стартовый экран как M3-UI-AC2: три карточки с иконкой, заголовком и описанием, последний сценарий обведён и показывает «последний раз: …», ↑/↓ выбирают, Enter и клик открывают; до трёх последних записей папки журналов («сегодня 10:15 · 42 мин»), клик открывает просмотр.
- [ ] U1-AC10 (FR-1, FR-2, FR-9, FR-11, FR-12, FR-14). Шаги трёх режимов как M3-UI-AC3: TCP-сервер (порт, автоответ «Авто» по умолчанию, крупный адрес для анализатора из списка интерфейсов с «Скопировать», строка про брандмауэр), TCP-клиент (адрес, порт, автоответ), COM (порт с описанием и «Обновить», скорость 300…115200 и «другая…», формат `8N1`/`7E1`, автоответ); «Дополнительно»: интерфейс прослушивания, переподключение, поток, DTR/RTS, анализатор, комментарий, папка журналов с выбором через диалог, «NAK на неверную сумму ASTM», профили.
- [ ] U1-AC11. Валидация и ошибки старта — текстом 12px под своим полем по коду ошибки (`port_in_use`, `address_unavailable`, `permission_denied`, `log_dir`, `port_not_found`, `port_busy`, `port_settings`, `address_invalid`, `serial`, `already_running`, `journal`, `io`); пустое поле не краснеет до первого «Старт»; файл журнала при ошибке старта не создаётся. Unit-тесты на правила валидации и привязку кодов к полям.
- [ ] U1-AC12 (FR-30). Профили: «Сохранить», выбор в списке меняет поля, «Удалить»; после перезапуска профили и последние настройки (сценарий, поля, папка, вид ленты, кодировка) на месте.

Шаг 3 — запись:

- [ ] U1-AC13 (FR-25). Запись идёт прямыми вызовами `bytetap-core::session` без IPC; события приходят через `broadcast` в кольцевой буфер 10 000 фрагментов; отставший подписчик не теряет счётчики и показывает «пропущено в ленте: N». Тест: 50 000 фрагментов через сессию на loopback — буфер не растёт сверх предела, счётчики совпадают с журналом.
- [ ] U1-AC14 (FR-25). Шапка записи как M3-UI-AC4: «Стоп» с пульсирующей точкой и таймером, сводка режима («жду на :5000 · HL7 (авто)», «подключено к …», «COM5 · 9600 8N1»), счётчики «→ … ← … N соед.», меню «…» (комментарий, папка журналов, скопировать путь, тема).
- [ ] U1-AC15 (FR-26, FR-27). Лента как M3-UI-AC5: время, глиф направления цветом, номер соединения при нескольких соединениях, `‹CR›` цветом `ctrl`, «автоответ», служебные строки `open`/`close`, `error` и `info`; виды «Текст» и «HEX»; кодировки ASCII, Windows-1251, GBK, UTF-8, Latin-1 через `encoding_rs`; фильтр соединений только при >1; трасса с двумя дорожками над лентой.
- [ ] U1-AC16 (FR-28). Лента виртуализирована (`show_rows`): при 10 000 строках прокрутка плавная, кадр рисует только видимые строки; прокрутка вверх останавливает догон и показывает «↓ N новых», клик возвращает вниз; копирование строки (текст, HEX, Base64) — через контекстное меню.
- [ ] U1-AC17 (FR-23, FR-20). Комментарий во время записи дописывает `note`; отказ журнала — строка под шапкой как M3-UI-AC8 с «Выбрать другую папку» и «Открыть записанное»; закрытие окна во время записи сначала штатно останавливает сессию (журнал заканчивается `session_end`), потом закрывает окно.

Шаг 4 — просмотр журнала:

- [ ] U1-AC18 (FR-29, FR-34). «Открыть журнал…» и последние записи открывают просмотр как M3-UI-AC7: шапка с именем файла, анализатором, длительностью; строка о персональных данных; комментарий журнала; лента постранично по индексу (страница ≤ 1000 событий, файлы 100+ МБ открываются без чтения целиком). Во время записи открытие журнала недоступно.
- [ ] U1-AC19. Карта сессии строится по индексу (плотность 600 корзин, `firstEvent`, длины фрагментов): клик переводит ленту к месту, рамка видимой области двигается при прокрутке; «Комментарий» дописывает `note`, который виден после повторного открытия; «×» возвращает стартовый экран. Логика индекса перенесена из `app/src-tauri/src/journal.rs` вместе с её тестами.

Шаг 5 — качество и выпуск:

- [ ] U1-AC20 (FR-25…FR-30). Паритет функций с UI v2 подтверждён ручным смоуком из [тестирования](/dev/testing), переписанным под нативное приложение: окно без рамки, стартовый экран, три сценария, автоответ «Авто»/HL7/ASTM, лента текст/HEX и кодировки, фильтр соединений, «↓ N новых», трасса, просмотр журнала с картой, комментарий, отказ журнала, тема, профили, последние настройки, закрытие во время записи.
- [ ] U1-AC21. Визуальное соответствие UI v2: снимки всех экранов 1200×800 в светлой и тёмной темах и 1366×768 согласованы владельцем; отступления (текст без ClearType, контекстное меню копирования) перечислены в `design.md`.
- [ ] U1-AC22 (NFR-7). `bytetap.exe` release ≤ 25 МБ (проверка размера в CI), окно с готовым интерфейсом появляется не позже 2 с от запуска на ноутбуке класса i5 и не позже 4 с на WARP.
- [ ] U1-AC23 (NFR-3). Владелец запускает exe на Windows 11 22000 с WebView2 90.0.818.66 и проходит сценарий записи HL7 до `session_end`.
- [ ] U1-AC24 (NFR-5). CPU в простое (окно открыто, записи нет) — около 0 % (кадры не рисуются без событий); во время записи с потоком 100 фрагментов/с частота перерисовки не выше ~30 кадров/с, сессия 8 часов не увеличивает память сверх буфера ленты.
- [ ] U1-AC25. Доступность через AccessKit: у каждого своего виджета (карточки, кнопки окна, иконочные кнопки, пилюля «Стоп», меню, поля, строки ленты) есть роль и подпись; Tab обходит элементы экрана в порядке чтения, Enter/Space активируют; проверка Экранным диктором (Narrator) и тест на дерево AccessKit.
- [ ] U1-AC26. DPI: интерфейс корректен на 100, 125 и 150 % масштаба Windows и при переносе окна между мониторами с разным DPI — без размытия иконок, обрезанного текста и смещённых кнопок окна.
- [ ] U1-AC27 (FR-31). Ввод кириллицы в полях «Анализатор», «Комментарий» и в диалоге комментария работает с русской раскладкой и через IME (композиция Windows), копирование и вставка через буфер обмена.
- [ ] U1-AC28 (T-6). Снимочные тесты `egui_kittest` всех экранов (стартовый, три шага, «Дополнительно», ошибки полей, запись в тексте и HEX, прокрутка с «↓ N новых», просмотр журнала, отказ журнала) в обеих темах; unit-тесты валидации, настроек, ленты, кодировок, индекса журнала, i18n. `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test` зелёные на ubuntu и windows.
- [ ] U1-AC29 (T-5). CI: job сборки Windows собирает `bytetap.exe` из `crates/bytetap-app`, проверяет размер и смоук-запускает его на `windows-latest` с поиском «интерфейс готов» в журнале запуска; `release.yml` упаковывает новый exe.
- [ ] U1-AC30. Удалены `app/` (Tauri и Vue), npm workspace `app`, jobs `frontend` и `windows-app` для Tauri; в `Cargo.lock` нет `tauri`, `wry`, `webview2-com`; npm в репозитории обслуживает только сайт документации.
- [ ] U1-AC31 (DOC-2, DOC-4). Документация: `guide/` без WebView2 и со свежими снимками, `docs/dev/architecture.md` (связь ядра и интерфейса, crate приложения), `docs/dev/design.md` (токены → `build.rs`, отступления от UI v2), `docs/dev/testing.md` (снимочные тесты, смоук), README, `CHANGELOG.md`; `npm run docs:build` зелёный. Тег `v0.2.0` ставится после ручного смоука владельца на черновике релиза.

## Вне рамок

- Windows 7 и 8.1: Rust ≥ 1.78 требует Windows 10, wgpu рассчитан на DX12 (ADR 0003).
- Прокси TCP (FR-5…FR-8) — этап M4, v0.3.0.
- Прослушка двух COM-портов (FR-10) — этап M5, v0.4.0.
- Английская локаль: архитектура i18n под неё готовится (U1-AC6), каталог `en` не входит.
- Новые функции интерфейса сверх UI v2.
