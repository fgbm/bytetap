# M0 — каркас

Цель этапа — работающий каркас проекта: сборка на Rust и фронтенде, CI, сайт документации, Windows exe-заглушка и черновик релиза по тегу. Логики захвата на этом этапе нет.

## Шаги

- [x] Cargo workspace и заготовки crates.
- [x] Tauri v2 + Vue 3 + TypeScript в `app/`.
- [x] Сайт VitePress в `docs/`.
- [x] npm workspaces и скрипты.
- [x] GitHub Actions.
- [x] CHANGELOG и `.gitignore`.

## Критерии приёмки

- [x] M0-AC1. Корневой `Cargo.toml` — workspace с членами `crates/bytetap-core`, `crates/bytetap-cli`, `crates/bytetap-testkit`, `app/src-tauri`; `rust-toolchain.toml` закрепляет конкретную стабильную версию Rust с компонентами rustfmt и clippy.
- [x] M0-AC2. `cargo tree -p bytetap-core` не содержит tauri.
- [x] M0-AC3. `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` проходят; в каждом crate минимум один тест-заглушка.
- [x] M0-AC4. `bytetap-cli --version` печатает версию из `Cargo.toml`.
- [x] M0-AC5. `app/`: Tauri v2 + Vue 3 + TypeScript + Vite; подключён vue-i18n, единственная локаль ru, строки окна-заглушки идут через i18n; заголовок окна «bytetap»; vitest с одним тестом; `vue-tsc --noEmit`, vitest и сборка фронтенда проходят.
- [x] M0-AC6. `docs/`: VitePress с `base: '/bytetap/'`, `lang: 'ru-RU'` и локальным поиском; навигация по разделам `guide/`, `reference/`, `dev/`; страницы-заготовки с заголовком и одной строкой «Раздел в разработке» там, где содержания ещё нет; существующие `docs/dev/requirements.md` и `docs/dev/stages/*.md` включены в сайт; битые ссылки ломают сборку; `npm run docs:build` проходит.
- [x] M0-AC7. Корневой `package.json` с npm workspaces `app` и `docs`, `package-lock.json` в репозитории; скрипты `dev`, `build`, `check`, `docs:dev`, `docs:build`; `npm run check` запускает fmt, clippy, cargo test, vue-tsc, vitest.
- [x] M0-AC8. `.github/workflows/ci.yml` на push и PR: job rust (матрица ubuntu-latest и windows-latest: fmt, clippy, test, на ubuntu установка системных пакетов Tauri), job frontend (vue-tsc, vitest, build), job docs (build), job windows-app (`tauri build --no-bundle`, exe в артефакт); кеш Rust и npm.
- [x] M0-AC9. `.github/workflows/docs.yml` публикует сайт на GitHub Pages при push в `main` с изменениями в `docs/**` и по `workflow_dispatch`.
- [x] M0-AC10. `.github/workflows/release.yml` по тегу `v*`: Windows-сборка, zip с `bytetap.exe`, README и LICENSE, файл `SHA256SUMS`, черновик GitHub Release.
- [x] M0-AC11. Все workflow проходят actionlint (если actionlint недоступен локально — отметить, что проверка выполнена в CI после push).
- [x] M0-AC12. `CHANGELOG.md` в формате Keep a Changelog с разделом Unreleased; `.gitignore` дополнен кешем и `dist` VitePress.
- [x] M0-AC13. Зелёный CI на GitHub и опубликованный сайт — проверяется после первого push владельцем.

## Итоги ревью

Ревью M0 пройдено; исправления по замечаниям перечислены в коммитах части A — идентификатор приложения, CSP и capabilities, `crate-type`, разделение release на build/publish, права и кеши workflow, `npm ls --all`, русские строки VitePress и проверка ссылок сайдбара, тест версии, README и эта страница.

AC1–AC12 были отмечены `[x]` раньше коммитов реализации — это нарушение порядка «критерий отмечается в коммите, который его реализует»; впредь отмечать вместе с реализацией.

Повторное ревью — две major (тема сайта при тёмной системе, имя архива vs SHA256SUMS) исправлены; вместе с ними закрыты мелкие замечания: токены подписи брендовой кнопки VitePress, плашки только у управляющих символов в примере обмена, `engines.node` в корневом `package.json`, неиспользуемый `--bt-hatch-opacity` и инлайнинг шрифтов в сборке приложения.
