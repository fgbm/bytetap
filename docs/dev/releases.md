# Релизы

## Что поставляется

Основной формат поставки — переносимый `bytetap.exe`: его копируют на ноутбук инженера и запускают без установки. Установщик (NSIS/MSI) пока не собирается: сборка идёт с `--no-bundle`, поэтому в CI появляется только exe.

В zip релиза входят `bytetap.exe`, `README.md`, `LICENSE` и `SHA256SUMS`. Имя архива — `bytetap-v<версия>-windows-x64.zip`, имя exe внутри архива — `bytetap.exe`.

WebView2 — компонент Windows, а не часть приложения. В `tauri.conf.json` стоит `bundle.windows.webviewInstallMode` = `{"type": "skip"}`: установщик не тянет загрузчик WebView2 из сети, а отсутствие среды ловится до создания окна системным окном сообщения (`NFR-3`). Офлайн-установщик, который кладёт WebView2 рядом с приложением, решается на этапе M6 вместе с подписью и обновлениями; до тех пор предупреждение объясняет, что установить среду нужно вручную.

## Процесс выпуска

1. **Подготовка.** Версия в `[workspace.package]` корневого `Cargo.toml` — `0.1.0`; от неё же берут версию `app/src-tauri` и ресурс версии exe (`tauri.conf.json` версию не задаёт). `app/package.json` и `CHANGELOG.md` согласованы с этой версией. В `CHANGELOG.md` раздел релиза заполнен, `Unreleased` пуст, ссылки сравнения на месте.
2. **Тег.** После зелёного CI на `main` владелец ставит аннотированный тег `v0.1.0` на коммит релиза и пушит его: `git tag -a v0.1.0 -m "bytetap v0.1.0"` и `git push origin v0.1.0`. Тег запускает `release.yml`; версия тега обязана совпадать с `Cargo.toml`, иначе workflow падает на шаге «Сверить тег с версией».
3. **Сборка.** Workflow собирает exe на `windows-latest` без установщика (`npm run tauri build -- --no-bundle`), кладёт `target/release/bytetap.exe` в zip вместе с `README.md` и `LICENSE`, считает `SHA256SUMS` и загружает артефакт.
4. **Черновик.** Второй job проверяет контрольную сумму и создаёт **черновик** релиза через `gh release create --draft --verify-tag --generate-notes`. Публикации на этом шаге нет: релиз виден только владельцу и команде.
5. **Смоук владельца.** Владелец скачивает zip из черновика, проверяет `SHA256SUMS`, запускает exe на Windows, проходит чек-лист из `docs/dev/testing.md` (в том числе M2-AC18: старт, обмен, стоп, просмотр журнала, темы, профили) и убеждается, что в свойствах exe и в имени архива одна версия.
6. **Публикация.** Владелец правит заметки релиза и нажимает «Publish release» в GitHub. После публикации обновляется ссылка `releases/tag/v0.1.0` в README и объявляется релиз.

## SmartScreen и подпись

До M6 релизы выходят **без подписи кода**: сертификат в бюджет проекта не входит. Поэтому каждый новый exe встречает SmartScreen предупреждением «Windows защитила Ваш компьютер»; это ожидаемое поведение, а не признак заражения. Проверить файл можно по `SHA256SUMS` из релиза. Пользовательская инструкция — `docs/guide/smartscreen.md`.

Подпись, установщик и автообновления — этап M6. До него release-workflow не подписывает exe, не публикует релиз автоматически и не трогает `latest`.
