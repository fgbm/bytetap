# ADR 0003. Нативный интерфейс на egui вместо Tauri и WebView2

- Статус: принято
- Дата: 2026-10-21
- Затрагивает: NFR-2, NFR-3, NFR-7, FR-25…FR-31, T-5, DOC-2, этап U1

## Контекст

Интерфейс v0.1.0 — Tauri v2 и Vue 3 поверх системного WebView2. WebView2 приложение не поставляет: оно берёт тот, что установлен в Windows, и его версия зависит от системы, а не от нас. На офлайн-ноутбуках, ради которых bytetap и сделан (раздел 2 требований), WebView2 обновляется вместе с Edge через Windows Update или не обновляется вовсе. На машине владельца Windows 11 22000 WebView2 застрял на 90.0.818.66, и автономный установщик Evergreen его не обновляет; Tauri-версия там не запускается. Инженер на выезде исправить это не может: прав администратора и интернета у него обычно нет.

Варианты внутри Tauri не снимают проблему целиком:

- Fixed Version WebView2 — своя копия рантайма рядом с exe. Это +180 МБ к дистрибутиву (NFR-7 требует десятков МБ, а не сотен) и отдельная настройка прав ACL на папку рантайма, иначе процесс песочницы WebView2 не запускается из пользовательской папки.
- Сообщение «обновите WebView2» (сделано в v0.1.0, NFR-3) честно объясняет отказ, но запись обмена на такой машине всё равно невозможна.

Windows 7 и 8.1 этим решением не возвращаются и остаются вне рамок: Rust ≥ 1.78 поддерживает только Windows 10+, последний WebView2 для Windows 7 — версия 109, wgpu рассчитан на DX12, который на Windows 7 недоступен.

Ограничения выбора:

- поставка — один переносимый exe без установщика, прав администратора и системных компонентов (NFR-2, NFR-3);
- размер — десятки МБ, запуск — секунды (NFR-7);
- работа на ноутбуке без драйвера GPU или со старым драйвером;
- живая лента 10 000 фрагментов без подтормаживания (FR-28);
- русский текст и ввод кириллицы, архитектура под второй язык (FR-31);
- ядро захвата и CLI не меняются: решение касается только оболочки.

## Рассмотренные варианты

- **Tauri как есть.** Готовый UI v2 и тесты, но приложение не работает там, где WebView2 устарел или удалён. Проблема не наша, а решать её некому.
- **Tauri и Fixed Version WebView2.** Работает независимо от системного WebView2, но дистрибутив вырастает примерно до 200 МБ, поставка — папка с рантаймом и правами ACL вместо одного exe, рантайм нужно обновлять вручную ради безопасности.
- **egui, eframe и wgpu.** Immediate mode GUI на чистом Rust, один статический exe. Отрисовка через wgpu на DX12, а без драйвера GPU — через WARP (программный растеризатор Direct3D, входит в Windows 10/11). Прототип `proto/egui` воспроизвёл экраны UI v2 (сценарии, форма сервера, запись с лентой) со шрифтами IBM Plex из TTF и иконками Lucide через resvg; лента на `show_rows` держит 10 000 строк. Оценка переноса — 27–40 человеко-дней.
- **Slint.** Декларативный язык разметки и нативная отрисовка, тоже один exe. Свой язык `.slint` и модель свойств — второй язык в проекте; виртуализированный список и кастомные виджеты ленты сложнее, чем в egui; лицензия GPLv3 или роялти-free с условиями атрибуции требует отдельной оценки для MIT-проекта.
- **Локальный веб-сервер и системный браузер.** Интерфейс остаётся веб-приложением, exe поднимает HTTP на `127.0.0.1` и открывает браузер. Снова зависимость от того, что установлено (браузер, его версия, политики), плюс открытый локальный порт, вопросы брандмауэра и вкладка вместо окна; закрытие вкладки не останавливает сессию.

## Решение

Интерфейс переписывается на egui и eframe с бэкендом wgpu:

1. Новый crate приложения `crates/bytetap-app` (bin `bytetap`, exe `bytetap.exe`, `windows_subsystem = "windows"`) зависит от `bytetap-core` напрямую, без IPC: управление — вызовы ядра, поток событий — подписка через `tokio::sync::broadcast` в кольцевой буфер интерфейса.
2. Отрисовка — wgpu на DX12; если адаптера с драйвером нет, используется WARP. Без GPU приложение медленнее, но работает.
3. Окно без системной рамки, своя шапка с кнопками окна — как в UI v2. Шрифты IBM Plex и иконки Lucide встраиваются в exe.
4. Работа ведётся в ветке `native-ui` этапом U1; `main` остаётся на Tauri и получает исправления до паритета. После паритета Tauri-приложение удаляется, релиз v0.2.0 выходит на egui.

## Последствия

- **Поставка.** Один exe ~15–20 МБ без зависимостей: не нужны WebView2, .NET, VC++ Redistributable и установщик. Требование — Windows 10 1809+ или Windows 11 x64.
- **Текст.** egui рисует глифы сам, без ClearType и субпиксельного сглаживания; на 100 % масштабе текст мягче системного. Смягчаем кеглем (основной текст не мельче 13 px, моно ленты — 12–13 px) и подбором хинтинга; итог согласует владелец по снимкам.
- **Выделение текста.** Свободного выделения мышью по нескольким строкам ленты, как в браузере, нет: механизм выделения egui сбрасывает выбор, как только один из его концов уходит за пределы видимой области, а лента виртуализирована. Поэтому выделение строк ленты — своё состояние в номерах событий (этап [L1](/dev/stages/L1)): строки выделяются кликом и Shift+кликом, а Ctrl+C копирует их с временем и направлением — это шаг 2 L1, в шаге 1 сделан только выбор строки. Полный фрагмент открывается в панели деталей снизу (шаг 1 L1) — там обычное выделение произвольного фрагмента мышью, Ctrl+A и Ctrl+C работают в поле только для чтения. Копирование из ленты контекстным меню строки (текст, HEX, Base64) остаётся. Горизонтальной прокрутки ленты нет: длинную строку читают в панели, где текст переносится по ширине. Переноса строк в ленте тоже нет — он ломает постоянную высоту строки, на которой держатся виртуализация, прокрутка просмотра и карта сессии. Решение и его цена — в [исследовании](/dev/research/feed-selection), согласовано с владельцем 2026-10-23.
- **Доступность.** В WebView2 роли и подписи давал браузер; в egui доступность идёт через AccessKit, и роль, подпись и порядок Tab у каждого своего виджета — обязательная работа этапа, а не бесплатное свойство.
- **i18n и настройки.** `vue-i18n` и `localStorage` заменяются своими модулями: строки ru на Rust с архитектурой под en (FR-31), настройки и профили — JSON в `%APPDATA%\bytetap`.
- **Дизайн-токены.** Сайт документации остаётся на VitePress, а токены остаются в `design/tokens.css` как единый источник для сайта и приложения: `build.rs` crate приложения разбирает CSS-переменные и генерирует Rust-константы цветов, размеров и радиусов. Правка токена — одна правка в одном файле.
- **Тесты.** Vitest заменяется снимочными тестами `egui_kittest` (все экраны в обеих темах) и unit-тестами состояния на Rust; смоук exe на `windows-latest` проверяет запись «интерфейс готов» в журнале запуска.
- **Ядро и CLI** не меняются. Логика, которая жила в мосте Tauri (`list_recent_journals`, индекс и страницы журнала, `diag.rs`), переносится в ядро или в crate приложения.
- **Удаление.** После паритета удаляются `app/` (Tauri и Vue), npm workspace `app`, jobs `frontend` и `windows-app` в CI; `release.yml` собирает новый exe. npm в репозитории остаётся только для сайта документации.
- **Риски.** Перенос — 27–40 человеко-дней; до паритета две реализации интерфейса живут в разных ветках, исправления UI v2 в `main` нужно повторять в U1. Immediate mode перерисовывает кадр целиком: CPU в простое должен быть около нуля (перерисовка только по событию), во время записи частота `request_repaint` ограничивается.
