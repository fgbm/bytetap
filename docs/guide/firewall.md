# Брандмауэр

В режиме «Вместо ЛИС · TCP-сервер» анализатор подключается к ноутбуку, то есть соединение входящее. Windows Defender Firewall по умолчанию такие соединения из сети не пропускает; при первом старте записи он показывает запрос «Разрешить доступ».

## Что ответить на запрос

В окне запроса перечислены типы сетей: «Частные», «Общедоступные» и, если компьютер в домене, «Доменные».

- **Частные сети** — разрешите: это сеть лаборатории или диагностического кабинета.
- **Доменные сети** — на компьютере в домене разрешите тоже: доменная политика может пропускать приложение только по этому профилю, и без галочки правило для доменной сети не появится.
- **Общедоступные сети** — не обязательно; включайте, только если анализатор физически в такой сети и вы понимаете, что порт открыт для всех в ней.
- Отказ или закрытие окна означает, что анализатор не сможет подключиться: в ленте не будет ни одного соединения, хотя сессия идёт.

Запрос появляется один раз на программу и профиль сети. Если окно случайно закрыли с отказом, правило можно поправить в «Брандмауэр Защитника Windows → Разрешить приложение…», но это уже требует прав администратора.

## Если сеть не опознана

Прямой кабель между ноутбуком и анализатором, без DHCP и шлюза, Windows считает неопознанной сетью и относит её к общедоступным, даже если в запросе вы отметили «Частные». Порт в такой сети останется закрыт. Варианты по порядку предпочтения:

1. **Назначить сети профиль «Частная»** — «Параметры → Сеть и Интернет → Ethernet → Свойства подключения» → «Профиль сети» → «Частная». Нужны права администратора; после этого запрос брандмауэра снова предложит «Частные сети», и одного разрешения хватит.
2. **Разрешить для общедоступных временно** — если профиль сети поменять нельзя: порт будет открыт для всех сетей, к которым подключён ноутбук, поэтому на постоянной работе так оставлять не стоит. Без прав администратора это тоже недоступно.
3. **Режим TCP-клиент** — исходящее соединение с ноутбука, которое брандмауэр обычно не блокирует; появится в следующей версии. До тех пор без прав администратора остаётся консольная `bytetap-cli` с тем же ограничением: она тоже слушает порт.

## Если запрос закрыли отказом

Отказ создаёт запрещающие правила: они сильнее разрешающих и будут молча закрывать порт, даже если позже разрешить bytetap в списке программ или добавить разрешающее правило. Строки отказа видно в журнале брандмауэра как «Query User» (по одной на профиль сети). Убрать их можно двумя способами:

- «Брандмауэр Защитника Windows → Разрешить взаимодействие с приложением» → «Изменить параметры» → снять галочки у bytetap или удалить строки кнопкой «Удалить».
- В PowerShell от имени администратора убрать все правила с именем программы:

  ```powershell
  Get-NetFirewallRule | Where-Object DisplayName -like 'bytetap*' | Remove-NetFirewallRule
  ```

  После этого запустите запись снова и ответьте на запрос «Разрешить».

## Без прав администратора

Разрешить входящее соединение может только администратор: правило брандмауэра — системная настройка. Варианты по порядку предпочтения:

1. **Попросить администратора** добавить правило для `bytetap.exe` (частные и доменные сети, нужный порт). Команда для администратора:

   ```powershell
   New-NetFirewallRule -DisplayName "bytetap" -Direction Inbound -Program "C:\Tools\bytetap\bytetap.exe" -Protocol TCP -LocalPort 5000 -Profile Domain,Private -Action Allow
   ```

2. **Проверить обмен без сети**: анализатор и bytetap на одном ноутбуке, адрес `127.0.0.1`. Годится для проверки настройки и демонстрации, но не для реального анализатора по Ethernet.
3. **Дождаться режима TCP-клиент** — исходящее соединение, которое брандмауэр обычно не блокирует; до его появления остаётся вариант 1.

Чего делать не стоит: отключать брандмауэр целиком «на время» — это открывает машину целиком, а не один порт.

## Если соединения нет, а правило есть

- Анализатор смотрит на другой адрес или порт: сверьте подсказку в форме настроек с настройками прибора.
- Ноутбук и анализатор в разных подсетях, между ними маршрутизатор с собственными правилами.
- Порт занят другой программой: bytetap покажет ошибку у поля «Порт» ещё до старта.

Прочие случаи — [Проблемы](/guide/troubleshooting).
