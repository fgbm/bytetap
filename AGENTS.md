# AGENTS

Правила работы агента с репозиторием bytetap.

## Проект

- Личный независимый open source проект (MIT) на GitHub владельца. Не упоминать и не привязывать к конкретным ЛИС, лабораториям, заказчикам и их данным.
- Источник требований — `docs/dev/requirements.md`, идентификаторы требований (FR-, NFR-, T-, DOC-) указывать в коммитах и PR, когда изменение их реализует.
- Порядок работ — этапы M0–M6 из `docs/dev/requirements.md`; границы релизов — `docs/dev/roadmap.md`.

## Процесс

- Каждый этап и требование нарезается в план и критерии приёмки в `docs/dev/stages/<этап>.md`.
- Если изменение затрагивает интерфейс, HTML-макеты согласуются с владельцем до написания кода.
- Затем цикл «реализация → код-ревью» до прохождения всех критериев приёмки.
- Критерии приёмки отмечаются `- [x]` по мере выполнения.
- Коммиты — conventional commits с идентификаторами требований.

## Код

- Ядро захвата — Rust crate `crates/bytetap-core` без зависимости от интерфейса.
- Интерфейс — нативное приложение на egui, eframe и wgpu: crate `crates/bytetap-app` (bin `bytetap`), ADR 0003. Строки — через `t!` и каталог `crates/bytetap-app/locales/ru.json`, цвета и размеры — из `design/tokens.css` через `build.rs`, снимки `egui_kittest` — `crates/bytetap-app/tests/snapshots/` (обновление: `UPDATE_SNAPSHOTS=1 cargo test -p bytetap-app --test snapshots` на Linux с lavapipe).
- Tauri v2 и Vue 3 (`app/`) — уходящая реализация: правки только для паритета, удаляется в шаге 5 этапа U1.
- Перед сдачей: `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test`, сборка фронтенда (пока `app/` не удалён).
- Не коммитить журналы реальных сессий (`*.jsonl` с данными приборов): они могут содержать персональные данные пациентов. Тестовые журналы — только синтетические.
